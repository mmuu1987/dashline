# 观察证据与设计推导

## 调研边界

本次只做玩法观察、运行日志与本地缓存资源命名核对，没有复制或提交参考游戏的代码、图片、音频、模型、配置文件或截图。《潮汐猎场》的名称、鱼种、海域、数值、UI 与商业规则均为原创方案。

## 证据—发现—设计路径

| 证据 | 发现 | 《潮汐猎场》的设计推导 |
|---|---|---|
| 结算画面显示本局得分、历史最高、新纪录和全国百分比 | 大数字与比较能强力推动复玩 | 保留个人最佳和真实好友榜；百分比必须来自有效数据 |
| 一局内经历多次鱼形态变化 | 局内形态成长是主要高潮节奏 | 设计 6 段进化，并在 3、4、5 阶加入三选一 |
| 运行日志出现分级肉块与大量鱼图标资源 | 猎物、掉落和图鉴共同形成内容梯队 | 用“鱼种阶级 + 肉块补给 + 四阶段图鉴”组织内容 |
| 日志出现治疗、攻击、体力、视野、经验、速度、幸运等效果资源 | 局内增益覆盖生存、机动与成长 | 首版收敛为 7 种颜色语义稳定的道具，同时最多 3 个 |
| 日志出现冲刺、毒、隐身、回复生命等表现资源 | 追逃由体型和状态共同改变 | 冲刺成为通用操作，毒与隐蔽成为可读特殊规则 |
| 日志出现宝箱贝壳、珍珠光效和奖励提示 | 定点高价值事件能打破持续游动的单调 | 设计 1.2 秒可打断的宝箱贝壳，占点换收益 |
| 日志出现复活界面资源 | 死亡前存在额外容错层 | 免费复苏珍珠与可选广告复活合计每局最多两次 |
| 缓存资源按场景、鱼种、技能、UI 分组 | 内容适合数据化分包和按需加载 | 按海域、物种、事件、表现四类资源包组织 |
| 鱼类动作资源包含巡游、转向、冲刺、攻击和眼部表演 | 表情与动作承担大量喜剧反馈 | 每种鱼规定最小动画集，眼神用于传达警戒和恐惧 |

## 观察事实与推断的区分

### 直接观察

- 横屏自由游动，核心对象为不同体型和形态的鱼。
- 结算页出现 19932 的本局分数、2737 的历史最高、新纪录徽章和 91.21% 的比较文案。
- 结算前已经经历多次形态变化、吞噬、受击、恢复、宝箱与复活相关流程。

### 日志与资源命名证据

- 存在多级肉块、多个战斗鱼与鱼类图标资源。
- 存在回血、攻击提升、体力、视野、经验、速度、幸运、隐身、中毒等效果资源。
- 存在贝壳宝箱、珍珠、复活、计分、新发现与新纪录相关资源。
- 存在多个场景/区域、鱼类巡游与多种攻击动画资源。

### 不能据此确认

- 参考游戏的精确伤害、经验、刷新权重和掉落概率。
- 排名百分比的计算样本、刷新周期与模式口径。
- 所有资源是否在当前版本和当前模式中实际启用。
- 具体服务端架构、反作弊策略和商业化转化数据。

因此，本策划案中的全部数值都属于新项目首版基线，需要通过原型和小规模测试校准。

## 原创差异化

- 以“风险路线”替代单纯堆鱼：安全鱼群、同阶猎物、宝箱和精英形成路径选择。
- 增加同阶失衡战斗，让体型相近时仍有走位与侧后攻击空间。
- 使用轮廓形状、颜色、边缘箭头三重威胁语言，降低大小误判。
- 将海域霸主设计成三次破绽吞噬，适合单指操作，不做复杂技能连招。
- 好友榜只比较同版本真实成绩，不显示无法解释的全国百分比。
- 付费只售外观和赛季收藏，不出售吞噬阶级与战斗力。

## 调研复核方法

1. 在授权机器上打开《鱼吃鱼》微信小游戏并完成一局。
2. 记录开局、进化、增益、宝箱、复活与结算流程。
3. 对照同一时间段的本地小游戏运行日志，确认资源和状态名称。
4. 将“观察事实”“资源证据”“策划推断”分别登记，禁止把推断写成原作事实。

调研截图和缓存文件不纳入策划案交付，避免携带第三方素材和本地账户数据。
